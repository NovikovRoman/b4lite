# Происхождение

Этот проект представляет собой выделение одной функции - прокси MTProto
(Telegram) - из [b4](https://github.com/DanielLavrushin/b4), гораздо более
крупного обработчика сетевых пакетов для обхода DPI, разработанного Daniel
Lavrushin (`DanielLavrushin/b4`, распространяется под лицензией GPLv3).

`internal/mtproto` и `internal/log` скопированы практически без изменений из
пакетов `src/mtproto` и `src/log` проекта `b4` (были переписаны только пути
импорта). `internal/config` - это новый, гораздо более простой тип
конфигурации, написанный так, чтобы удовлетворять именно то, что нужно
`internal/mtproto`, вместо полной конфигурации приложения b4 (которая также
охватывает наборы для обхода DPI, перехват DNS, захват пакетов и десятки
других не связанных с этим функций).

Все остальное - `cmd/mtproto-proxy/main.go`, `go.mod` и этот файл - написано
заново, чтобы превратить выделенный пакет в самостоятельный исполняемый файл.

Поскольку основная часть кода является производной от программного
обеспечения, лицензированного под GPLv3, этот проект распространяется под
той же лицензией - см. `LICENSE`.

Не аффилирован с Daniel Lavrushin и не одобрен им.

## Синхронизация с апстримом

Исходное выделение было сделано с коммита `ad324ba` upstream-репозитория
(2026-08-23). По состоянию на 2026-09-16 из апстрима перенесены
относящиеся к `internal/mtproto` изменения по коммит `701bc908`
(2026-08-29) включительно:

- фикс, из-за которого Telegram-клиент мог посчитать прокси
  "неправильно настроенным" и отключить его - сессия, случайно
  попавшая на media-edge дата-центра (`kwsN-1`), получала пакет ошибки
  `-444`, который ретранслировался клиенту вместо того, чтобы быть
  перехваченным и обработанным сменой маршрута;
- пропуск IPv6-адресов при дозвоне до WebSocket-edge, если у хоста
  нет реального IPv6-маршрута (а не просто выключен флаг в конфиге);
- race condition в счётчике одновременных web-carrier-соединений;
- доверие заголовку `X-Forwarded-For` только от локального/приватного
  пира (иначе интернет-клиент мог подделать свой IP в логах и обойти
  лимит сетей на секрет);
- необязательный лимит числа одновременно используемых сетей на один
  секрет (`max_networks`, см. `README.md`).
